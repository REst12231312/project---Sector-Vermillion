# Sector: Vermillion

Игровой сайт по Warhammer 40,000 с React-интерфейсом и отдельным Node.js API на Express.

## Структура

- `frontend/` — React-приложение.
- `backend/app.js` и `backend/index.js` — настройка Express и запуск API.
- `backend/routes/` — HTTP-маршруты.
- `backend/services/` — авторизация и игровая бизнес-логика.
- `backend/storage.js` — чтение и запись JSON-хранилища.
- `backend/data/gameData.js` — игровые справочники; сохранения, пользователи, состояние онлайн-операций и ключ авторизации хранятся отдельно в той же папке и не добавляются в Git.

## Запуск в Windows PowerShell

Установи зависимости один раз:

```powershell
cd frontend
npm install
cd ..\backend
npm install
```

Затем запусти API и сайт в отдельных окнах PowerShell:

```powershell
cd backend
npm run dev
```

```powershell
cd frontend
npm start
```

Интерфейс откроется на `http://localhost:3000`, API — на `http://localhost:4000`. Игровые записи API сохраняет в `backend/data/progress.json`.

## Сетевые операции

Войди под двумя аккаунтами в разных браузерах или профилях и открой в каждом `/online`. Для быстрого боя нажми «Найти противника». Для игры с другом создай частную комнату, отправь ему код, выбери фракцию и нажми «Готов»; бой начнётся после готовности обоих. В онлайн-матчах доступны Империум, Хаос, Орки и Тау. После боя оба игрока могут согласиться на rematch.

Сервер ограничивает ход 60 секундами, автоматически пропускает просроченный ход и даёт отключившемуся игроку 90 секунд на переподключение. Повтор команды с тем же `actionId` возвращает сохранённый ответ, а команда с чужим или повторно использованным идентификатором отклоняется. Матчи и частные комнаты сохраняются в `backend/data/online-state.json` и восстанавливаются после перезапуска API. Авторизованный участник получает актуальное состояние при переподключении; сервер проверяет владельца отряда, очередь хода и каждое действие.

Комната принимает максимум двух игроков; её владелец может закрыть её до боя, а гостевой слот можно освободить после окончания матча. Во время активного боя выйти можно через сдачу.

Первый игровой прототип включает поле 12×12, препятствия и укрытия, по три отряда Империума, Хаоса, Орков и Тау, серверные броски D6, три точки захвата и оба условия победы. Между матчами случайно меняются стартовая сторона, инициатива и зеркальная ориентация целей. После атаки интерфейс показывает каждый бросок попадания, ранения и спасброска. Правила находятся отдельно от API в `backend/game/battleEngine.js`.

Для повторного прогона симуляции баланса используй:

```powershell
cd backend
node scripts/simulateBalance.js --matches 5000 --max-turns 40
```

Чтобы сравнить все шесть пар фракций, добавь `--all-factions` (число матчей лучше задавать кратным 48, чтобы равномерно покрыть пары, инициативу, стороны и ориентации целей):

```powershell
node scripts/simulateBalance.js --all-factions --matches 6000 --max-turns 40
```

Средний урон оружия против всех вражеских профилей можно пересчитать отдельно:

```powershell
node scripts/analyzeFactionBalance.js
```

Проверка основных правил движка запускается так:

```powershell
node scripts/verifyBattleEngine.js
```

Симулятор играет обе стороны одним и тем же ИИ, который перемещается к целям и применяет D6-атаки, спасброски и урон. Он сравнивает победы фракций и пар, стороны поля и инициативу, длительность и условия победы. Это воспроизводимая проверка баланса, но она не заменяет игры с людьми. Результаты и ограничения текущего прогона описаны в [отчёте о выполнении этапов](backend/reports/stage-verification.md).

Автоматические сценарии сетевой игры запускаются так:

```powershell
cd backend
npm test
```

Набор проверяет жизненный цикл частной комнаты, выбор фракций, лимит участников, готовность, параллельные команды, повтор атаки после потери ответа, сохранение после перезапуска отдельного процесса, таймеры хода и переподключения, синхронизацию состояния, сдачу и повторный бой.

При первом открытии создай аккаунт по ссылке регистрации. Имя пользователя должно быть длиной 3–24 символа (латиница, цифры, `_`), пароль — не короче 8 символов. Пароли хранятся в виде хешей; игровые API доступны только с действующим токеном входа. Данные аккаунтов, прогресс и ключ подписи токена находятся в `backend/data/` и не добавляются в Git.
